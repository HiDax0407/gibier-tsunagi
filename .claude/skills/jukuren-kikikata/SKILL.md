# 熟練の業を引き出す聞き方（ジビエつなぎ）

ベテランの話を、新しく入る人が使える「手順」と「注意」にするための聞き方。
画面での写しは `public/lib/kikikata.js`（型の中身はこのファイルが正。変えるときは両方を直す）。

## 聞き方の型（6つ）

| 型 | 何を引き出すか | 聞き方の例 |
|---|---|---|
| 失敗談 | 手順書に出てこない落とし穴 | 「〇〇で、うまくいかなかったときのことを教えてください」 |
| 良し悪しの見分け方 | 目で見て・手で触って分かること | 「〇〇で、良いときと悪いときは、どこで見分けますか？」 |
| 感覚と量（どのくらい） | 時間・回数・量の目安 | 「〇〇は、どのくらいが目安ですか？」 |
| 昔と今の違い | 変わった理由（道具・天気・獣の数） | 「〇〇は、昔と今で変わったところはありますか？」 |
| 新人がよくやる間違い | 教えるときに一番伝えたいこと | 「〇〇で、新しく入った人がよくやる間違いは何ですか？」 |
| 話の食い違いの確認 | 前の話と今の話のずれ | 「前は〜、今日は〜とお話しでした。どちらが近いですか？」 |

## 進め方

1. 工程（見回り／わなの設置・点検／止め・搬送／処理（洗浄・解体）／冷蔵・保管／出荷・店とのやりとり／記録（日付・場所））ごとに、話に出てきたかを見る
2. まだ出ていない工程があれば、そこを先に聞く。全部出ていれば、型で深く聞く
3. **聞き返しは1回に1つだけ。** 質問を2つ並べない。短く、やさしい言葉で
4. 話した言葉は方言も言い直しもそのまま残す。標準語に書き換えない。言っていないことを足さない

## してはいけないこと

- 答えない・教えない：捕獲や処理のやり方、法令、衛生、資格の決まり、見回りの決まりについて、AI が答えたり断定したりしない。話に出たら「本人の話」として残し、「チームと県・市町村の窓口で確認（要確認）」と添える
- 人を評価しない：話し方・うまさ・人に点数や順位をつけない
- 体のぐあいの話は聞かない・残さない（見守りは「話した日」だけ）
- 生々しい言い方を引き出さない・使わない

## 出す形

```json
{ "step": "わなの設置・点検", "kata": "新人がよくやる間違い", "question": "わなの設置・点検で、新しく入った人がよくやる間違いは何ですか？", "why": "まだ話に出ていない工程" }
```
